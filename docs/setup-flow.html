AutoAdmin setup flow and where it can get expensive

This traces the first-time setup in PLAN.md, from "@AutoAdmin I want a 1.21.1 Fabric superflat server with 3 mods" to a running server. Steps sit in the lane of whoever does the work. Every arrow into the Claude lane resends the whole conversation, so that's where API cost builds up.

Status: phase 2 isn't built yet, so this is the planned flow. Sizes and costs are estimates for Sonnet 5.5 at current prices.

One full setup, two designs

Claude drives every step $1–3

About 40 calls. Raw outputs push the context to 40–60k tokens. A non-admin hits the $0.50 per-user cap partway through setup.

Coarse tools, code does the work $0.08–0.20

10–14 calls with the context kept under ~12k tokens. Claude parses the request, settles ambiguities, handles failures and reports. Progress messages come from code.

Both are estimates from Sonnet 5.5 pricing: $2 input, $2.50 cache write, $0.20 cache read and $10 output per million tokens. We'll replace them with measured numbers once phase 2 runs.

What this changes in the phase 2 design

  1. Setup runs as a job in code. One start_setup(spec) tool kicks off a pipeline: version, Java, loader, properties, mods, start. The harness posts progress lines to Discord directly, with no model call. Claude is only called back for decisions and failures.
  2. Every tool result is capped and summarized. No raw manifests, installer logs, or API listings ever enter the context.
  3. Claude never polls. Long operations either wait in code or report back as an event.
  4. Human questions are batched into one message, and the shared prompt prefix gets its own cache point.
  5. Downloads go through one checksum-keyed cache with bounded retries, and the heap size comes from free RAM.
